## 0. Nomenclature — say these words, not other words

The menu lives in `Data/Spanish/layers/sense_menu/spanishdict.json`. Verbatim
structure, with the vocabulary this project should use for each level:

```
"quedar":                          <- SURFACE FORM (the dict key; the word as it appears)
  [                                <- a LIST of ANALYSES, one per headword the form can be
    { "headword": "quedar",        <- HEADWORD (= lemma, dictionary form)
      "senses": {
        "a79": {                   <- SENSE ID; one entry here is a LEAF
          "pos":         "VERB",         <- SpanishDict's tagset, NOT Universal Dependencies
          "translation": "to be left",   <- the GLOSS. This is what the card prints.
          "context":     "to be available", <- SpanishDict's USAGE NOTE
          "headword":    "quedar",
          "source":      "spanishdict",
          "examples":  [ { "original": "...", "translated": "..." } ],
          "regions":   [...]              <- only 7.7% of leaves
        },
        "c63": { ... "translation": "to remain",       "context": "to be available" },
        "3c8": { ... "translation": "to be left over", "context": "to be available" }
      } } ]
```

| term | means | note |
|---|---|---|
| **surface form** | the inflected word as it appears | 9,945 have menus |
| **analysis** | one headword's senses for that surface | 16,553; a surface can have several (`fuera` -> `fuera`/`ser`/`ir`) |
| **headword** / **lemma** | dictionary form | |
| **leaf** | one sense id — the atomic unit | 96,279 leaf-instances, **31,236 distinct** (shared across inflections) |
| **gloss** | the `translation` field | the English on the card |
| **context** | the `context` field | usage note; groups leaves |
| **tuple** | `(headword, POS)` | the repo's word for it — `util_5c_token_prototypes.tuple_of`. 8,078 of them |
| **menu** | every leaf available for one surface form | mean 9.7, median 7, p90 22 |
| **glosskey** | `(POS, gloss, headword)` | leaf with the context stripped. What the 200-item panel labels, and the metric to optimise |
| **contextkey** | `(POS, headword, context)` | the *sibling* collapse — NOT a superset of glosskey. Both contain leaf; neither contains the other |

The four metrics form a lattice, and mixing them is how this session confused
itself. Same v5 picks on the 144-item panel:

    leaf         (pos, headword, gloss, context)   84.7%
    glosskey     (pos, headword, gloss)            84.7%   >= leaf, always
    contextkey   (pos, headword, context)          85.4%   >= leaf, sibling of glosskey
    "card gloss" (pos, gloss)                      85.4%   <- loose usage; do not say this

**Optimise glosskey.** Leaf is too fine — it scores `to say` -> `to say` under a
different sense id as a regression. Contextkey is only 1.5-3pp looser and is not
what the learner reads. Glosskey is the tightest metric that never punishes an
invisible difference.

Note the card DOES print the context: 92.9% of shipped meanings carry one and
`js/flashcards.js:91 joinSpokenGlossAndContext` renders and speaks them together.
So the 200-item panel's glosskey labels are **blind to a wrong context under a
right gloss** — a real limitation of that panel.

Two facts about the schema that matter more than they look:

- **`pos` is not Universal Dependencies.** SpanishDict files determiners as ADJ
  and has no AUX, NUM or PART at all. This has now caused two separate bugs.
- **95.6% of leaves have exactly ONE example** (mean 1.04). Any plan that leans
  on the dictionary's own examples is leaning on a single sentence per sense.

## 2. The constraints, and what was learned about each

### "Expensive offline, cheap online — amortisation even if I don't need it yet"

Sound in principle; **does not bind in speech mode yet.** The speech deck is a
one-off batch (~30k slots, static JSON). There is nothing to amortise over:
labelling it outright costs **$1.89**. Prototypes to do the same job cost ~$29
and score *worse*. Break-even for amortisation is roughly **150 user decks**.

### "Escalation to an oracle is allowed"

Confirmed, and cheaper and better than the repo believed.

- **Flash-Lite 3.5: 94.0%. DeepSeek-chat: 93.0%.** Parity — the ceiling is not
  proprietary, so self-hosting stays open.
- Real cost **$0.063 per 1k picks**, not the $0.047 the formula at
  `step_6e_assign_senses_calibrated.py:634` computes. 597 input tokens per pick,
  not 347. Output is 8 tokens — no reasoning-token blowup.
- The shipped escalation prompt says **"one line of song lyrics"** even in speech
  mode. Reframing it as subtitles is worth **+1.5pp** (94.0% vs 92.5%). Unfixed.

### "Must extend to missing or insufficient menus"

**Untouched, deliberately.** 1 of 200 panel items; historically ~4%. No mechanism
proposed handles it.

### "Doesn't need 100% — kill error CLASSES, not aggregate points"

The most load-bearing thing said all session; it reframed every metric.

- **81%** of the cheap path's errors and **58%** of Flash-Lite's are inside the
  same `(POS, headword)` — *only the gloss differs*. `to end`/`to finish`,
  `all`/`everything`, `some`/`any`.
- The menu **factorises**: 7.78 leaves per hard tuple = ~5.7 glosses x ~5.3
  contexts, and **45% of contexts span more than one gloss**. Within a context,
  the glosses are synonyms (`quedar [to arrange to see]` -> *to meet, to agree to
  meet, to arrange to meet*).
- **Static leaf-merging is the wrong fix, and this is Josh's argument, not
  Claude's:** acceptability is a property of the OCCURRENCE, not of the leaf
  pair. Two leaves can be interchangeable in one sentence and clearly distinct in
  the next. The right decision unit is `(POS, headword, context)` — SpanishDict's
  own annotation, not anyone's taste.

### "Tuple errors are not acceptable"

Near-saturated already. Residual is reflexive `X`/`Xse` (51.6% of tuple errors)
and POS (17.3%), per the existing notes. **Not worked on this session.**

### "One stronger mechanism, not ten heuristics"

**Not found.** Three candidates tested; all failed or underperformed (§4).

## 3. The difficulty landscape

Josh's (a)-(b) axis, measured on a deliberately **hard** 200-item panel
(`pipeline/wsd_harness/panels/hard_200_2026-08-23`):

| | accuracy | cost |
|---|---|---|
| (a) commonest sense | 67.3% | free |
| commonest + POS filter | 74.4% | free |
| **v5, as shipped** | **78.4%** | free |
| leaf prototypes + POS | 75.4% | free |
| (b) Flash-Lite / DeepSeek | **94.0% / 93.0%** | $0.063/1k |

The "~80% naive" figure in earlier notes comes from the older, easier 144-item
panel, where it is 81.9%. This panel is harder by construction.

**The middle, as currently reachable** — escalate by disagreement between the
three cheap methods:

| escalate | accuracy |
|---|---|
| 0% | 76.4% |
| 10% | 83.4% |
| **41%** | **91.0%** |
| 100% | 94.0% |

41% of the cost buys 87% of the available gain. Routing by agreement clearly
beats routing by menu size or at random. This is not elegant and it is not a new
mechanism, but it is the only *measured* way to occupy the middle.

## 4. Ideas tested and killed this session

| idea | verdict |
|---|---|
| **Leaf prototypes** — a meaning represented by the averaged BETO token vector of its real uses, instead of by its gloss text | 75.4%, **below v5**. Depth is everything: with <=5 examples behind the correct meaning it is **-11.5pp vs the prior**; 6-12 **+7.7**; 13+ **+10.7**. The deck's median depth is **4**. |
| **Distil from a better teacher** | Prototypes land ~3pp under their teacher, which is what distillation does. Only pays with a teacher that beats v5 — Flash-Lite does — but see amortisation. |
| **Aligned English as the core mechanism** | A **perfect** aligner decides outright on only **42%** of items and **51%** of failures. Strong partial signal, not a solution. |
| **Static leaf merging** | Wrong, per §2. Superseded by the gloss/context factorisation. |
| **Syntactic frames predicting context** | Failed. `echar`'s five contexts all look like "verb + direct object". Only `haber` (auxiliary vs existential *hay*) and `estar` (locative via `en`) separate cleanly. What *does* discriminate is fixed expressions (`tener cuidado`, `echar un vistazo`, `seguir` + gerund) — collocation, not syntax. |
| **Switching to WordNet / BabelNet** | Would make it **worse.** Those inventories are *more* fine-grained than a learner dictionary, and the existing notes already record OMW Spanish as worse than SpanishDict. Coverage was never the problem; granularity is, and no dictionary ships this product's cut. **Consider this question closed.** |

## 5. Modes

**Speech mode (current).** Menu coverage good, one-off build. The $1.89 direct
Flash-Lite option is available today for +15.6pp over v5.

**Artist / lyrics mode (later).** Needs sense invention. The shipped escalation
prompt is already lyrics-framed. Prototypes built on subtitle Spanish applied to
lyrics is untested register transfer. This is where amortisation and a
`(sentence, word)` cache start paying — songs repeat across users.

**Scaling past 10,000 surface forms.** Work grows with **distinct lemmas**, not
surface forms: 9,945 forms collapse to 8,078 tuples and 31,236 distinct leaves.
The binding constraint on growth is **scraping more menus**, not labelling cost.

After POS and headword are known, **92% of surface forms are still ambiguous**,
carrying 93.3% of corpus occurrences — only 8% become singletons. But 64.4% have
<=6 leaves left, so the residual is a small closed set per word.

## 6. Shipped this session

- **The AUX bug.** `sense_compatible_bridged('VERB', 'AUX')` returned `False`,
  rejecting every leaf and firing the empty-keep-set fallback — so the POS filter
  was a **silent no-op on `haber, ser, estar, deber, saber`**, the commonest verbs
  in speech. Same tagset mismatch as the DET->ADJ bug, missed when that was fixed.
  Worth **+14 items of 199** — but see the stratification caveat in §9: that
  panel is 35% AUX by construction, so the deck-wide value is proportionally
  smaller. The bug itself is not a measurement artifact; its headline size is.
  Fixed, tested, committed (`760170a2`).
- **The 200-item hard panel**, tracked in the repo, labelled at meaning level.
  The AUX fix scores **-1** on the old 144-item panel and **+14** here — the old
  panel cannot resolve a 7pp effect.
- **Two corrections to `wsd_algorithm.md`, still unapplied there:**
  1. The gloss embeddings are worth **+11.1pp** on hard words, not the ~2pp its
     144-panel ablation implies. Do not quote 2pp as a general claim.
  2. Its escalation cost is labelled "(measured)" but is a formula output, and
     it is 34% low.

## 7. Open

- **`mwe_phrases.json` is never opened by the classifier.** 1,246 words' fixed

  `grep -c mwe step_6e` returns 0. `junto a` -> "together", `sitio web` ->

- The `"song lyrics"` framing in the speech-mode escalation prompt (+1.5pp).
- `wsd_algorithm.md` still carries both wrong numbers from §6.
- The gloss/context factorisation is the right *framing* but has **no cheap

## 8. v6 — three roles instead of seven stages

Implemented in `pipeline/util_6g_v6.py`, tested in `pipeline/test_util_6g_v6.py`.
**Defaults reproduce v5 exactly: 199/199 identical picks on the hard panel.**
Everything new is opt-in and off.

v5 is a pile of stages with no shared contract, so nobody can say what any of
them is for. Every one of them does exactly one of three jobs:

| role | job | mechanisms |
|---|---|---|
| **1. CONSTRAIN** | remove candidates that cannot be right | POS filter (bridged), clitic gate, MWE match, companion word |
| **2. RANK** | one score over the survivors | menu prior, gloss embedding, domain vector |
| **3. COMMIT** | decide *how specific* an answer to emit | the three marginals |

### Role 3 is the only new idea, and it came from Josh

v5 always emits a leaf, so an uncertain pick is a **wrong** card. v6 can emit a
leaf, a glosskey (gloss without context) or a tuple (headword+POS) — an
uncertain pick becomes a **less specific** card instead.

    tuple + gloss + context confident  ->  leaf      "está — is (location)"
    tuple + gloss confident            ->  glosskey  "está — is"
    tuple confident only               ->  tuple     "estar — to be"
    tuple uncertain                    ->  escalate

Escalation triggers on the **tuple** margin alone, deliberately: a weak gloss
margin means the model is torn between synonyms, which the learner never sees
once the answer is emitted at glosskey level; a weak tuple margin means it may
have the wrong word entirely, which is never acceptable.

**The format already supports this** — 7.1% of shipped meanings carry no
context, so a glosskey-level answer renders today with no schema change. The
*display* side is `js/`, which is Codex's boundary.

Declining to over-claim is the one move that is always available and never
wrong, which is more than can be said for any mechanism measured on 2026-08-23.

### What v6 deletes

- **the calibrator** — replaced by the three marginals, and it is the broken
  component anyway (58% of the deck reads "low")
- **leaf repair** — becomes a special case of role 3; an empty gloss is a leaf
  you cannot defend, so you emit the glosskey
- **the escalation band logic** — one rule: escalate iff the tuple margin is weak
- **the BETO tuple vote** — folded into rank, or dropped

### Measured on the hard panel

    v5                        156/199   78.4%
    v6 defaults               156/199   78.4%   (199/199 identical picks)
    v6 + companion veto ON    158/199   79.4%   (+2)

The companion note (`'to support; used with "por"'`) is already parsed by
`companion_of` and used only to repair a *rendered* leaf. Used as a veto before
the pick, it is +2 items and free.

### Unmeasured, hence defaulted off

- **the three commit thresholds.** Calibrating them is role 3's entire evidence
  base and needs the frequency-sampled panel described in §9.
- **`aggregate="sum"` in `marginals`.** +8 on the hard panel, +1 on the
  unstratified 144, **-8** on the dictionary panel. It is a largest-tuple prior
  in disguise, which the repo had already identified once. Default is `"max"`,
  which provably reproduces the v5 argmax.
- **`domain_weight`.** Isolated domain matching scores 92.6% against a 43%
  prior, but its marginal value *on top of* the concatenated gloss vector is
  untested.

## 9. The hard-200 panel has a stratification bias — read this before quoting it

Stratifying on AUX / REFL / POLY over-samples words whose correct answer sits in
a **large tuple** — `haber`, `ser`, `tener`, `estar` all have huge menus. So any
heuristic that favours the biggest tuple scores well there and nowhere else.

Caught by testing sum-pooling across three panels:

| panel | Δ from sum-pooling |
|---|---|
| hard 200 (stratified) | **+8** |
| opensubtitles 144 (real, unstratified) | +1 |
| spanishdict 150 (dictionary examples) | -8 |

The -8 does not count — that panel is uniform over senses by construction and
cannot see frequency effects. But the +8 / +1 gap is the tell.

**Consequence:** every number from the hard-200 is soft in the same direction,
including the AUX fix's +14. The remedy is a second panel sampled by **corpus
frequency** rather than by difficulty class, which would let both the AUX fix
and the multiplicative combination be measured without the tuple-size bias.

## 10. Three more mechanisms died on the same rock

Added 2026-08-23, after §4:

| idea | verdict |
|---|---|
| **Specialist per context category** | Ceiling is ~5% of decisions. Domain 3.5%, used-with 0.8%, grammatical 0.6% — and **81% of occurrences land in "paraphrase/other"**, which is 4,408 distinct one-off strings whose top 25 cover only 8.9% of the bucket. There is no set of categories to write specialists for. |
| **Spread-based triage** (embed the candidate contexts; if they are close, the confusion is harmless) | Separates at the extremes but fails in the middle: 4 of 5 hand-graded WRONG cases land in the "safe" bucket. `está` "he's" vs "is" have identical contexts and 0.91 gloss similarity, yet "he's" on a card about a room is plainly wrong. |
| **Multiplicative combination of the marginals** | Unresolved. +8 on the biased panel, +1 on the clean one. See §9. |

**The pattern all three share** — and it is Josh's own argument, made about
merging several exchanges earlier: *acceptability is a property of the
occurrence, not of the leaf pair.* Any static, precomputed, occurrence-independent
property fails, because whether swapping two senses breaks a card depends on the
sentence. Which is why the model that actually reads the sentence sits 15 points
clear, and why role 3 (emit less) beats any attempt to decide better.
